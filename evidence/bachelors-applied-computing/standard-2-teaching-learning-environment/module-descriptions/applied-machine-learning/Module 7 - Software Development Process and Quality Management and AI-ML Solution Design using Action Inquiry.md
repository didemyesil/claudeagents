# Module 7: Software Development Process and Quality Management & AI/ML Solution Design using Action Inquiry

**Year:** 3 | **Code:** 07.ML | **Learning Line:** Professional Practice Line | **ECs:** 12.5

Develops software development process management and quality practice in Year 3, building on Module 5 (applied data science/ML foundations) and Module 6 (team inquiry). Covers SDLC approaches, agile/lean method selection, work planning/monitoring, iterative delivery, retrospectives/feedback loops, version control, code review, testing, and continuous integration. Learning via workshops, guided self-study, standups, squads, retrospectives, team coaching, and practice-based project work. Structured 8-week module concluding with a Module Project analysing/improving a software development process and its quality practices.

## Connection with the Research Practice Line

Team inquiry via Plan–Act–Observe–Reflect: examine a process/quality challenge, select and test an improvement, observe effects on workflow/software outcomes, reflect on what to retain/change — treating methodology and quality as integrated professional responsibilities.

## Intended Competencies and Learning Outcomes

**Software development process management** — apply appropriate methodologies (e.g. agile) to manage the software development process; use professional practices (version control, testing) to enhance delivery quality.

## Module Planning (8 weeks)

Week 1: Software Development Lifecycle and Method Selection. Week 2: Agile Software Development (Scrum/Kanban, roles, backlogs, sprints, standups, reviews/retrospectives). Week 3: Lean Software Development (customer value, value-stream, reducing waste, flow, continuous improvement). Week 4: Planning, Monitoring, and Delivery Control. Week 5: Version Control and Code Review. Week 6: Testing Strategy and Software Reliability. Week 7: Continuous Integration and Quality Controls. Week 8: Integrated Process and Quality Management Project.

## Weekly Study Load (41 hrs total)

Process and quality coursework/Module Project (blended): 25 | Self-study (online): 4 | Workshops (online): 2 | Standups (campus): 2 | Squads (campus): 4 | Team Coaching (campus): 4

## Assessment

**Low-stake:** workshop/sprint reflections, standup participation, squad participation, team coaching contributions.
**Medium-stake:** Module Project — analysis/improvement of a software development process and quality practices in an authentic/realistic context (context, methodology rationale, workflow plan, delivery evidence, version-control/testing evidence, quality findings, improvement action, reflection, synthesis).
**High-stake:** Certification VIVA (end of Certification 3).

**Passing criteria:** same structure as other Certificate 3 modules — ≥75% low-stake, ≥75% medium-stake, Certification VIVA passed.

*(Note: per the "Programme Inconsistency and Accuracy Check" in this folder, the module's title claims "AI/ML Solution Design using Action Inquiry" scope that its actual intended outcomes, activities, project, and VIVA evidence do not cover — they address software process/quality management only.)*

# Applied Machine Learning – Programme Inconsistency and Accuracy Check

Desk-based review checking the eight Applied Machine Learning module descriptions (as at 5 August 2026) against the TER, Educational Handbook, Assessment Policy, Final Project Guide, programme brochure, approved ML competency/modular-LO source, Qwasar AI/ML Curriculum (Sep25), and the NVAO Assessment Framework (effective 1 April 2024). The March 2026 curriculum is excluded. Each entry states the evidence, NVAO relevance, and required correction before submission.

## Flagged Inconsistencies, Accuracy Risks, and Verified Controls

| Finding and Evidence | Accuracy Assessment and Required Action |
|---|---|
| **HIGH — Programme volume and route conflict.** TER defines the BSc Applied Computing as 240 EC. The brochure describes a 3-year 180 ECTS full-time/fast-track route, and the 8 ML module descriptions total 180 EC. | NVAO Standards 1–2. Unresolved; materially affects the legal programme profile, curriculum coherence, and published information. Define the accredited 240 EC structure and state exactly how the fast-track route accounts for the remaining 60 EC (e.g. formal exemptions or RPL). Align TER, brochure, curriculum overview, and module set. |
| **HIGH — Final 60 EC not allocated** in the ML module-description set. Current documents end at 180 EC even though the programme is 240 EC and earlier decisions reserve a final-year Solution Design and Final Project phase. | NVAO Standards 2–3 and Standard 4 readiness. Add the separately approved 60 EC final-year structure (module codes, EC, duration, prerequisites, activities, LOs, assessment evidence, assessor roles, progression rules). Do not treat the current 180 EC set as complete. |
| **HIGH — Module 7 title/content mismatch.** Title includes "AI/ML Solution Design using Action Inquiry," but intended outcomes/activities/medium-stake project/VIVA evidence address software development process and quality management only. | NVAO Standards 1–3. Either separate AI/ML Solution Design into its own approved final-year module, or add approved solution-design outcomes/activities/criteria/evidence to Module 7. Title currently overstates assessed scope. |
| **HIGH — Module 8 title/content mismatch.** Title includes "AI/ML Graduation Project," but planning covers Qwasar Season 3 projects and Certification 3 only — no individual graduation-project brief, design/implementation phases, supervisor process, final deliverables, or final-project VIVA. | NVAO Standards 2–3 and Standard 4 readiness. Create a distinct Graduation Project module or integrate the approved Final Project Guide requirements explicitly. Exit-level assessment must be visible/traceable; current module should not be presented as the graduation project. |
| **HIGH — Inconsistent end-of-track representation** between brochure and module files (process/quality, solution design, advanced applications, graduation project not represented consistently). | NVAO Standards 1–2. Approve one canonical module architecture; use it consistently in brochure, curriculum overview, TER appendices, module titles/codes/EC/assessment plan before further content editing. |
| **HIGH — No approved ML project–learning-outcome mapping exists.** No ML equivalent of the separate Data Science project–LO mapping; current project associations were inferred from project content. | NVAO Standards 2–3. Approve a traceability matrix linking every ML project/assessment to module LOs and programme outcomes (e.g. Visa for Lisa → data analysis/ML solution design/model development/advice; Atari Games → deep learning/model evaluation). |
| **MEDIUM — Source-status conflict** in ML alignment material — a hidden "LOs_Applied ML" draft contains earlier wording ("Professional Advise") and extra unapproved competency labels (Software architecture design, Information retrieval, AI application development), absent from the approved ML competency set. | NVAO Standards 1–3. Treat the approved ML competency/modular-LO tab as sole authority; label/archive the hidden draft as non-approved with version/approval date/owner. Current module descriptions correctly use "Professional advice" and exclude the unapproved standalone competencies. |
| **MEDIUM — Module 5 titled "Applied Data Science"** but carries ML track code 05.ML and assesses ML solution-design/model-development outcomes; bridging role plausible but not formally explained. | NVAO Standards 1–2. Document the bridging function (data prep/analysis → supervised modelling/evaluation → advanced ML); confirm title/scope in the canonical curriculum map. |
| **HIGH — Qwasar AI/ML Curriculum (Sep25) project timing not reconciled** with compressed week allocations in Modules 1, 3, 5, and 8. | NVAO Standard 2. Approve one workload baseline reconciling project duration, teaching weeks, certification periods, independent study, and EC. Preserve Qwasar package/order; revise timing only via explicit curriculum decision. |
| **HIGH — Module 1 workload arithmetic inconsistent.** 15 EC = 420 study hours, but 11 project weeks at ~41 hrs/week already = 451 hours before the 2 orientation weeks are counted. | NVAO Standard 2. Recalculate activity-level hours for every module against 28 hrs/EC. For Module 1, adjust weekly load/teaching duration/EC to reconcile. Record orientation and post-module certification hours explicitly. |
| **HIGH — Assessment Policy defines low-stake as formative, not counted toward mastery scores**, yet module descriptions make a 75% low-stake threshold a progression condition, listing standup/squad/team-coaching participation as evidence. | NVAO Standard 3. Clarify whether the 75% rule is a completion condition or outcome-achievement evidence. Attendance/participation alone should not evidence mastery — use assessable artefacts/observations/reflections with criteria, aligned with the Assessment Policy. |
| **HIGH — Assessment requirements not fully transparent at module level.** Medium-stake projects must meet an "expected"/"required" standard and the VIVA is high-stake, but module files don't identify project-specific criteria, rubrics, assessor roles, calibration, resit rules, or the controlling assessment document. | NVAO Standard 3. Add an assessment blueprint or precise cross-references (criteria, evidence rules, assessor independence, moderation/calibration, decision rules, feedback, resits, Examination Board oversight) per assessment type. |
| **HIGH — Exit-level traceability incomplete.** Final Project Guide describes design/implementation phases, integrated bachelor-outcome demonstration, individual work, supervision, and final VIVA, but the ML module set contains no approved programme-outcome-to-final-project mapping or exit-level assessment matrix. | NVAO Standards 2–3 and Standard 4 readiness. Map every programme outcome to final-project deliverables/criteria; state how individual achievement, bachelor level, assessor independence, and the final decision are demonstrated/safeguarded. |
| **MEDIUM — Terminology varies:** "Applied Machine Learning," "Machine Learning," and "AI/ML" used inconsistently across sources (brochure-derived Module 7/8 titles use AI/ML while the track field uses Applied Machine Learning). | NVAO Standards 1–2. Approve a terminology table distinguishing legal programme name, track name, module title, and abbreviated technical label. Use "Applied Machine Learning" consistently for the track; reserve "AI/ML" only where part of an approved module title. |
| **VERIFIED CONTROL — Qwasar project-package sequence preserved.** In Module 8 the order is Visa for Lisa → Classically Punk → My_Paypal → Atari Games; projects not split/resequenced. Approved ML wording used for module LOs. | Method: Sep25 Qwasar sequence, approved ML competency/LO source, and Module 8 planning table compared side by side — sequence and LO wording passed; missing authoritative project–LO mapping and workload reconciliation remain open. NVAO relevance: Standards 2–3. |
